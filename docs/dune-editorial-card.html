PART 01

Dune 核心三原则

RULE 01

常规路径决策成本更低

让“正确的做法”更简单显见。正常路径自动化且顺畅，捷径充满阻力甚至被系统机制阻止。

目标：让系统自动引导 Agent 做对的事，而非依赖其理解复杂架构。
RULE 02

禁止的依赖自动触发失败

任何越界调用或破坏模块隔离的行为必须立刻失败。通过编译器、Lint 和 CI 自动 enforce 架构。

目标：防止 Agent 在局部上下文中做出看似能工作却破坏架构的代码。
RULE 03

异常狭窄明确且作为架构审查

例外绝不能随意产生或隐式蔓延。影响必须就地收敛，显式标注，任何例外都必须作为架构事件审查。

目标：避免例外变成隐性耦合点，彻底杜绝技术债务污染主路径。
多层约束体系
代码架构 > 静态分析 / 编译器 / CI > 审查规则 > Skills > 风格指南
前两者为违规必阻断的硬底线；后三者为辅助引导的软约束
PART 02

AI Agent 规模化落地：10 条实践总结

MODULE A 信任建立与闭环验证

01
信任是核心前提：通过实践积累体感并逐级授权，才能从管理 1~3 个 Agent 扩展到成百上千个并发协同。
02
自主闭环打破瓶颈：赋予 Agent 运行与验证能力（CDP、快照、模拟器），否则人类会成为吞吐量天花板。
03
用户视角精准定位：针对复杂应用编写用户视角功能地图，或通过截图/录屏反馈 Bug，辅助 Agent 快速定位根因。

MODULE B Skill 研发与质量工程

04
Skill 是高价值 Token：持续观察 Agent 失败原因，将隐性约束与业务上下文提炼为可复用的 Markdown 指令集。
05
像对待业务代码一样测试 Skill：制定评分 Rubric，子 Agent 执行测试，独立 Agent 交叉打分，循环优化直到满分。
06
从本地走向云端自动化：本地摸索沉淀规则后推向云端，自动拉起桌面复现 Bug 并确认主干修复，全面释放人力。

MODULE C 刚性架构与约束防御

07
早期硬规范阻断腐化：原型项目无规范会诱导 Agent 频繁走捷径，必须在早期设计硬性约束以支撑大规模自动化。
08
规范硬编码进架构与 CI：靠文档和人工 Review 约束 Agent 极不可靠，必须将防御规则直接写进编译器与 CI 门禁。
09
构建多层防御梯队：架构 > 编译/CI > 审查规则 > Skills > 风格指南。前两者是刚性底线，后三者为易遗忘的软引导。

MODULE D 前期重投与组织飞轮

10
前期 Token 投资的复利：前期重投在架构和测试上能节省数月/数年维护成本；坚固底座还能让 PM、设计师直接通过 Agent 提交生产代码，形成全员飞轮。
✦
架构启示：面对 AI 时代的代码爆发，最有效的管理手段不是“人盯代码”，而是“架构管系统”。
